# D14 商品属性与基础字典域 — 逻辑数据模型

> 数据源：`test_erp.sql`（唯一事实来源），逐表核对。全库无显式外键，"主/外键线索"与"关联"均为**推断**。
> 共 **34 张表**。**标准字典结构**（多数表符合）：`id`(PK) + `name` + `status` + `sort` + 审计四字段(created_time/created_by/updated_time/updated_by) + `delete_status`。下文各表仅列出**相对标准结构的差异字段**与关键信息，标准字段不再重复展开。

**标准字典列定义**（除非某表另注）：`id` bigint；`name` varchar(255)；`status` tinyint(1) 默认1；`sort` int/bigint 默认50；`created_time/updated_time` datetime；`created_by/updated_by` varchar(255) 或 varchar(50)；`delete_status` tinyint(1) 默认0。

## 本域小结

- **同构字典主体**：约 24 张表符合"标准字典结构"，仅 id 自增策略、字符集、sort/status 类型存在细微差异。
- **非标业务表**：`jf_basic_craft`（工艺枢纽）、`jf_fabric_specs`（规格度量）、`jf_craft_wastage`（损耗度量）、`jf_color_dyeing_task`（打色同步，无审计）、`jf_datat_dict`（KV）、`jf_basic_data_table`（元数据）——结构差异大，是建模问题集中点。
- **重复/弃用**：category↔catregory、dyeing_method↔staining_category(弃用)、fabric_category↔fabric_structure、paper_tube↔plastic_bag、sales/sku/spu 三套销售类别。
- **服务他域**：本域是 D09 商品、D08 客户、D01 订单等主数据的字典底座，跨域引用密集但均无外键约束。
