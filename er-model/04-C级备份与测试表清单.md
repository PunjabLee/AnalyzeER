# C 级 · 备份表（_bak_日期）与测试表（test_）清单点名 + 排除说明

> 数据源：`test_erp.sql`（唯一事实来源）。C 级共 **120 张表** = 备份表 **117**（匹配 `*_bak_<14位时间戳>`）+ 测试表 **3**（匹配 `test_*`）。
> 处理方式：**逐表点名 + 给出排除逻辑模型的理由**，不绘制 ER、不展开字段（结构与源表同构，字段模型已在对应 A/B 级域覆盖）。此清单可核验、零遗漏。

## 一、排除总则（为何不纳入 ER/逻辑模型）

1. **快照副本，非独立实体**：`*_bak_<时间戳>` 是对某业务/平台表在某时刻的**全量复制备份**（表名 = 源表名 + `_bak_` + 备份时间），列结构、含义与源表完全一致，不构成新实体，画进 ER 会与源表重复。
2. **一次性运维产物**：备份时间戳暴露其为分批运维快照（见第三节批次分布），随迁移/改造临时生成，属数据运维范畴而非数据模型范畴。
3. **测试/验证表**：`test_*` 为开发/测试期间的样例或对照表，非生产实体。
4. **命名边界（口径透明）**：仅"带 `_bak_<数字时间戳>` 后缀"与"`test_` 前缀"计入 C 级。形如 `jf_goods_bak`、`jf_stock_product_msg_bak`、`jf_customer_complaints_bak`、`jf_ownership_transfer_application_product_bak`（**无时间戳的 `_bak` 结尾**）以及 `jf_business_inventory_20251230`、`jf_business_inventory1`、`jf_sales_order_copy1`、`jf_statement_fee_category_copy1`、`jf_rebate_query_temp` 等，按既定分组**保留在 A 级 jf_ 业务域**逐表处理（其口径调整说明已记录于本文件第六节）。

## 五、C 级小结

- 备份 117 + 测试 3 = **120**，与第三节数量校验一致（lcap 51 + jf 2 + 无前缀 64 = 117）。
- 全部为**源表的整表快照/测试副本**，逻辑模型已由 A/B 级对应源表覆盖，故**不再单独建模**，仅点名留痕以满足"一张不遗漏"。
- **风险提示（供模型问题清单引用）**：备份表与测试表混居于生产库中（尤其 `remark_information`、`trace_quota` 等源表归属待确认者亦有备份），反映**库表生命周期治理缺失**——备份/临时表未隔离到独立 schema 或及时清理。
