## R-0【P0·核心订正】GraphRAG 定性：拆「抽取层（冗余）」与「社区/全局层（真实增量）」

**问题**：原 §1.2 把 GraphRAG 与 AgenticRAG 直接定为"主线+叠加层"（路线结论先行）；评审团反驳时又把 GraphRAG 的差异化价值压缩为"仅自然语言综述、非刚需"——这**低估且误述**了 GraphRAG。两处都要改。

**事实依据（仅凭 er-model）**：
- 抽取层确实冗余：关系已由 `01-ER图/Dxx`（逐条关系线 + 证据标签，如 D01 L188 `[注释明示]`）、`03-逻辑数据模型`（`FK[目标·依据]` 内联）、`05`（5 子图 / 43 条核心关系）**人工判定并结构化落盘**——让 LLM 再抽取 schema 既有失真风险又无增量。
- 社区/全局层是确定性遍历与关键词检索**给不出**的增量：
  1. **全局/整体性问题（global sensemaking）**："全库真正的枢纽实体、域间耦合最紧处、跨域影响主传导路径"——需社区检测 + 分层摘要 + map-reduce。
  2. **涌现式跨域簇**：对 1322 表跑 Leiden/Louvain，可暴露 `00` 手工 18 域**未覆盖**的跨域团（按度数中心性浮现的隐藏 hub、`05` B-4"同名列异指向"造成的假耦合团）。
  3. **多跳 + 叙事联合**：血缘/影响的完整链路叙述（附各跳证据与风险点）。
  4. 直接服务 **UC6「按业务域检索/摘要」**——评审团自认这是 GraphRAG 唯一显著加分点，不应再降格为"非刚需"。

**关键落点**：这部分价值**不需要重型独立 GraphRAG 栈**即可获取——在确定性属性图上跑社区算法 + 预生成域/社区摘要即可（轻量"社区摘要层"）。

**修订动作**：
- 原 §1.2「推荐落地形态：以 GraphRAG 为知识底座…三者分层组合」→ 改为分两层评估的表述：
  > **推荐**：确定性属性图（结构已由 er-model 落盘，LLM 抽取层可省）为主干；在其上叠加**轻量社区/全局层**（社区检测 + 分层社区摘要），服务全局性问题、涌现跨域簇、UC6 按域摘要；向量层与 AgenticRAG 编排为**由实测缺口触发的可选增强**，非默认底座。
- 原 §1.3.4「能用图查询回答的不纯 LLM 生成」→ 保留，并补一句边界：
  > 确定性可答的（精确检索/单跳/多跳遍历）走结构化查询；**全局综述与涌现簇属"遍历给不出"的一类**，由社区摘要层承担，不等同"锦上添花的自然语言润色"。
- 评审报告措辞订正：
  > ❌「GraphRAG 仅在'自然语言综述'占优（非刚需）」
  > ✅「GraphRAG 的**抽取层**在本资产冗余可省；其**社区检测+分层摘要**带来的全局性问题/涌现跨域簇/UC6 按域综述是确定性方法的真实增量，只是**可低成本单独取得**，无需重型栈。」
