# D05 发票与税务域 · ER 图（数据源：test_erp.sql）

> 覆盖 13 张表。全库 **0 外键约束**，关系均为逆向**推断**，标注：`[注释明示]`/`[索引佐证]`/`[命名推断]`/`[语义推断]`/`[待确认]`。带 `[跨域引用]` 实体在他域定义。
> 本域以 **发票申请 `jf_invoice_application`（购销双方 + 收寄 + 冲红 全快照大表）为核心**，围绕开票全流程：开票信息主数据（贸易商/客户/类型）→ 发票申请 → 状态跟踪日志 / 费项开票明细 → 百望接口异步日志 → 税费单（已作废）。**关键现象：存在三对几乎同构的重复表**（`jf_invoice`↔`jf_trader_invoice`、`jf_invoice_information`↔`jf_customer_invoice_information`、`jf_invoice_type`↔`jf_customer_invoice_type`），疑为迁移/重构遗留。

## 关系要点与证据摘录

| # | 关系 | 基数 | 依据强度 | 证据原文 |
|---|---|---|---|---|
| 1 | 发票申请 → 状态跟踪日志 | 1:N | **注释明示+索引** | `invoice_application_id COMMENT '关联申请表 ID (jf_invoice_application.id)'`；`INDEX idx_app_id` |
| 2 | 发票信息 → 客户 | 1:N | 注释明示+索引 | `customer_id COMMENT '客户id（关联客户表）'`；`INDEX idx_customer_id COMMENT '客户id索引，优化查询'`（invoice_information / customer_invoice_information 两表同款） |
| 3 | 发票申请 → 结算/开票单位 | N:1 | 注释明示 | `buyer_agreement_unit_id COMMENT '协议单位id(jf_settlement_unit)'`、`sales_invoice_unit_id COMMENT '开票单位id(jf_settlement_unit)'` |
| 4 | 费项开票明细 → 发票申请/费项池 | N:1 | 命名推断 | `invoice_fee_detail.invoice_application_id`、`fee_item_id='费项池ID'` |
| 5 | 税费单 → 税费单明细 | 1:N | 命名推断+索引 | `tax_bill_detail.tax_id='税费单ID'`；`INDEX idx_tax` |
| 6 | 发票申请 ↔ 收款单 | N:N | 命名推断(编码) | `collection_bill_codes='已选择收款单号'`（**多单号存字符串**）[跨域 D04] |
| 7 | 收票信息 → jf_invoice | 1:1 | 命名推断·存疑 | `express_recipient_id='客户收票信息id'`（目标表 jf_invoice / jf_trader_invoice 均"收货单位"表，`[待确认]`） |

## 本域模型问题速记（详见逻辑数据模型）
1. **三对同构重复表（迁移遗留）**：`jf_invoice`↔`jf_trader_invoice`（"贸易商的开票信息表"字段完全一致）；`jf_invoice_information`↔`jf_customer_invoice_information`（"发票信息表"仅字符集不同）；`jf_invoice_type`↔`jf_customer_invoice_type`（后者缺 `sort`）。职责边界不清，应废弃其一（P-D05-01）。
2. **`jf_tax_bill` / `jf_tax_bill_detail` 表注释"作废"仍在 A 级**：税费单主子表均已弃用但未归档（P-D05-02）。
3. **反序主键**：`jf_tax_bill` 定义 `PRIMARY KEY (id DESC)`，罕见的降序聚簇主键（P-D05-03）。
4. **字段名与语义冲突**：`jf_tax_bill.audit_status` 名为"审核状态"实存"1未付款2已付款3作废"（付款状态）；`delivery_address_id` 名为"交货地址id"注释却写"关联最终厂家"（P-D05-04）。
5. **非自增主键普遍**：`invoice`、`invoice_application`、`invoice_baiwang_async`、`invoice_type`、`customer_invoice_type`、`trader_invoice` 均 bigint 非自增（应用层/雪花 ID 生成），与自增主键表混用（P-D05-05）。
6. **编码/多值串关联**：`invoice_application.collection_bill_codes`（多收款单号存字符串）、`invoice_fee_detail.source_order_code`/`fee_code` 以单号关联，无 id 外键（P-D05-06）。
7. **状态枚举多套**：`invoice_application.status`(1-8)、`log.stage_type`(字符串枚举)、`tax_bill.audit_status`(varchar 1-3)、`invoice_type.status`(tinyint 无枚举说明)（P-D05-07）。
8. **字符集混用**：`unicode_ci`（invoice/trader_invoice/invoice_type/customer_invoice_type/invoice_information）与 `general_ci`（invoice_application 全家族/customer_invoice_information/tax_bill）并存，同构对子内部字符集都不一致（P-D05-08）。
9. **关联目标存疑**：`express_recipient_id`（收票信息 id）、`collection_account_id`（收款账户 ID）指向表在本域未见定义 `[待确认]`（P-D05-09）。
