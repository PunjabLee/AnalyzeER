# D06 费用与结算域 · ER 图（数据源：test_erp.sql）

> 覆盖 15 张表。全库 **0 外键约束**，关系均为逆向**推断**，标注：`[注释明示]`/`[索引佐证]`/`[命名推断]`/`[语义推断]`/`[待确认]`。带 `[跨域引用]` 实体在他域定义。
> 本域以 **费项池 `jf_fee_item`（费项明细，86 列巨型宽表）为绝对核心**，围绕"费项"贯穿单据（费项单 `jf_fee_bill` + 三张挂单明细）、流水审计（`jf_fee_item_flow`）、责任划分（`jf_assign_responsibility`）、费用主体（`jf_expense_subject`/`jf_cost_principal`/`jf_expense_subject_department_mapping`）与结算单位（`jf_settlement_unit`）。**核心问题：`jf_fee_item` 一张表塞入收款/认领/开票/税费/核销/退款六类状态各一份**；且存在"费用主体""费项类型"多表语义重叠。

## 关系要点与证据摘录

| # | 关系 | 基数 | 依据强度 | 证据原文 |
|---|---|---|---|---|
| 1 | 费项池 → 费项流水 | 1:N | 命名推断+索引 | `flow.fee_item_id COMMENT '费项ID'`；`INDEX idx_fee_item_id COMMENT '费项ID索引'` |
| 2 | 费项单 → 单据-费项 | 1:N | 命名推断+索引 | `fee_bill_item.fee_bill_id`；`INDEX idx_fee_bill` |
| 3 | 费项单 code ↔ 费项池 fee_code | 1:1 | 命名推断(编码) | `fee_bill.code='单据编号(费项池的code)'` ↔ `fee_item.fee_code`（**编码关联，非 id**） |
| 4 | 费项池 → 收款/认领/核销/退款/发票 | 1:N(占用) | 命名推断(编码) | `fi.collection_notice_code`/`receivable_claim_code`/`write_off_occupy_code`/`refund_occupy_code`/`invoice_application_code`（**五类占用编码，均字符串**） |
| 5 | 费项类别 → 费项/费项单 | 1:N | 命名推断+索引 | `fee_category_id` + `idx_fee_category` |
| 6 | 客诉责任 → 质量赔偿 | N:1 | 命名推断+索引 | `assign_responsibility.quality_compensation_id`；`idx_customer_complaints` [跨域 D15] |
| 7 | 结算明细 → 销售单/返利 | N:1 | 命名推断+索引 | `settlement_detail.sales_order_id`/`rebate_id`；`idx_order` [跨域 D01/D12] |

## 本域模型问题速记（详见逻辑数据模型）
1. **`jf_fee_item` 巨型宽表（违反单一职责）**：86 列，塞入收款通知/应收认领/收款/开票/发票申请/税费/核销/退款 **八类状态与占用编码各一份**（`status`/`claim_status`/`payment_status`/`invoice_status`/`invoice_occupy_flag`/`tax_*`/`write_off_occupy_*`/`refund_occupy_*`），应垂直拆分（P-D06-01）。
2. **"费用主体"同构重复**：`jf_expense_subject` 与 `jf_cost_principal` 表注释均为"费用主体"，字段近似（id 一个自增 bigint/一个非自增、cost_principal 另有 `no`）；"费项类型"`jf_expense_type` 与"费项管理"`jf_fee_category` 语义亦重叠（P-D06-02）。
3. **拼写缺陷**：`fee_item.curency_code`（应为 currency，缺 r）、`assign_responsibility.satus`（应为 status）、`over_due` 与 `is_over_due` 并存、`quality_compensation_id` 注释"质量不损ID"（compensation 义为赔偿，注释错字）（P-D06-03）。
4. **类型/约束异常**：`fee_item.over_due` 为 `tinyint(1) UNSIGNED ZEROFILL`（布尔用 zerofill 怪异）；`expense_type.sort` 为 bigint；`department_id` 用 varchar 存部门 id（expense_subject_department_mapping / assign_responsibility）；`fee_item` AUTO_INCREMENT=2103345217727737860（异常量级）（P-D06-04）。
5. **编码关联反范式**：`fee_bill.code`↔`fee_item.fee_code`、五类 `*_occupy_code`/`*_notice_code`/`*_claim_code`、`associate_sales_code`、`sales_order_code` 均以业务单号关联，无 id 外键（P-D06-05）。
6. **重复/冲突注释**：`fee_bill_sales_order.unit_price_discount` 与 `discount_total_amount` 注释同为"单价优惠金额"；`fee_item` 内多组 `*_occupy_flag` 注释文案完全相同（P-D06-06）。
7. **作废/弃用字段**：`fee_bill_item.write_off_amount`/`un_write_off_amount`（"作废"）、`fee_item.review_write_off_invoice_amount`（"弃用"）（P-D06-07）。
8. **字符集列级混用**：`fee_item` 内 `*_occupy_code` 列为 unicode_ci、其余 general_ci；`expense_subject_department_mapping` 内 `department_name` 单列 unicode_ci；`expense_type`/`cost_principal` 整表 unicode_ci 与域内 general_ci 并存（P-D06-08）。
9. **归属存疑**：`jf_settlement_detail`（"年底返利结算明细"）语义属 D12 返利域；`jf_assign_responsibility`（客诉责任划分）关联 D15 质量赔偿——现按既定分组保留于 D06，此处记录口径备注（P-D06-09）。
10. **主键自增性/无注释**：`expense_type.id`、`cost_principal.id` bigint 非自增；`fee_bill.trader_id`、`fee_bill_sales_order.sales_order_code` **无 COMMENT**；`fee_category` 表注释"id 为 1-20 的数据不允许更改"为隐式规则，无约束保证（P-D06-10）。
