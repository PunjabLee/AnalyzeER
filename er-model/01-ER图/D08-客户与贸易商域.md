## 关系要点与证据摘录

| # | 关系 | 基数 | 依据强度 | 证据原文（COMMENT / 命名） |
|---|---|---|---|---|
| 1 | trader → customer | 1:N | 命名推断+业务强 | `customer.trader_id bigint NOT NULL COMMENT '贸易商id'` |
| 2 | customer → customer_account | 1:1 | **注释明示** | `customer_account_id ... COMMENT '客户账户余额(关联jf_customer_account)'` |
| 3 | customer → contract_quota_customer | N:1 | **注释明示** | `quota_customer_id ... COMMENT '授信额度(关联jf_contract_quota_customer)'` |
| 4 | trader_quota → cash/credit_quota_record | 1:N | **注释明示** | `trader_quota_id ... COMMENT '交易商额度主键'` |
| 5 | trader_attribute → trader | 1:N | 命名推断 | `trader.attribute_id ... COMMENT '贸易商属性id'` |
| 6 | catregory ↔ trader（经 mapping） | N:M | 命名推断 | `trader_category_mapping(trader_id, category_id)` |
| 7 | trader → trader（上级） | 自关联 | 命名推断 | `trader.superior_unit ... COMMENT '上级单位'` |
| 8 | company → company（上级） | 自关联 | 命名推断 | `company.sup_id ... COMMENT '上级公司名称'` |
| 9 | 各画像字典 → customer | 名称冗余 | **语义推断（弱）** | customer 端存 `trade_type/enterprise_nature/...` varchar 名称，非 id |

## 本域模型问题速记（详见逻辑数据模型）
1. **画像字段反范式**：客户 8+ 个画像维度（贸易类型/企业性质/经营模式/生产规模/价格定位/主营类目/重要程度/客户状态）均以 **varchar 存名称**而非引用字典表 id，字典表又独立存在，二者无 id 关联 → 更新传播困难、`customer.customer_status` 甚至是 tinyint 与字典表 id(bigint) 类型不匹配。
2. **作废字段未清理**：`jf_customer` 保留 `customer_account_balance / coupon_amount / credit_line / payment_method / brand_series / is_overseas` 等 6 个注释标"作废"的字段；`jf_customer_receipt_information` 整表注释"作废"。
3. **命名/拼写缺陷**：类别字典同时存在 `jf_category`（客户/贸易商类别）与 `jf_catregory`（拼写错误，贸易商类别）两套；额度流水外键命名不一致（正式用 `trader_quota_id`，修改记录用 `trade_quota_id`）；`jf_customer.pay_form_id` 名带 _id 但注释"不再关联表"。
4. **表注释缺失**：`jf_trader_quota_process_apply` 无 COMMENT。
5. **域归属存疑**：`jf_customer_complaints_bak`（客诉，关联质量补损）、`jf_customer_color`（产品客户色号，关联产品）名义属客户域，实际强绑 D15/D09，归属需业务确认。
