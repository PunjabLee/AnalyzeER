# D02 备货与报价域 · ER 图（数据源：test_erp.sql）

> 覆盖 21 张表。全库 **0 外键约束**，关系均为逆向**推断**，标注：`[注释明示]`/`[索引佐证]`/`[命名推断]`/`[语义推断]`/`[待确认]`。带 `[跨域引用]` 实体在他域定义。

## 关系要点与证据摘录

| # | 关系 | 基数 | 依据强度 | 证据原文 |
|---|---|---|---|---|
| 1 | 客订备货 → 订金流水 | 1:N | **注释明示** | `reservation_stock_id ... COMMENT '关联的客订备货ID（jf_reservation_stock.id）'` |
| 2 | 报期单 → 现货备货 | 1:N | 命名推断(按单号) | `pot.report_order_code='备货报期单号'` → `period.order_code` |
| 3 | 备货主表 → 产品明细 | 1:N | 命名推断(按 order_code) | `product_msg.order_code`（非 id） |
| 4 | 报价申请 → 商品明细 | 1:N | 命名推断 | `goods.quotation_application_id`（表注释"作废"） |
| 5 | 整染进度 ↔ 备货单 | M:N | 命名推断 | `stock_progress.order_code` 为 **text**（存多值串） |
| 6 | 备货 → 收款通知单 | 1:1 | 命名推断(按 code) | `rs.notice_link_code='预付定金收款通知单号'` [跨域 D04] |
| 7 | OA流程/审核记录 → 各备货单 | N:1(多态) | 命名推断(按 order_code + type) | `modif.type`='2现货3客订'、`oa.order_code` |

## 本域模型问题速记（详见逻辑数据模型）
1. **三张 `_import` 表无主键**：`jf_quotation_application_import`、`jf_reservation_stock_import`、`jf_stock_pot_replenishment_import` 均以 `id bigint NOT NULL DEFAULT 0` 且**无 PRIMARY KEY 定义**，为数据导入暂存表，违反主键约束。
2. **业务单号 order_code 作全局关联键**：几乎每张备货子表都靠 `order_code`（字符串）关联主表，无 id 外键；`stock_progress.order_code` 甚至为 **text 存多值**，无法建有效索引。
3. **主键自增性不统一**：`quotation_application.id`、`sales_stock_review_modif_record.id` 为 bigint **非自增**（应用层生成）；`_import` 表 id 默认 0。
4. **备份/作废表混入**：`jf_stock_product_msg_bak`（_bak 但无日期后缀，与在用 product_msg 结构重叠）、`jf_quote_goods_detail`（表注释"作废"）留在 A 级。
5. **颜色 id 类型不一致**：`reservation_stock_product_msg.color_id` 为 bigint，而 `stock_pot_replenishment_product_msg.color_id` 为 **int**；`spu_id` 多处无注释。
6. **命名/拼写问题**：`prepayment_percen`（应为 percent）、`bal_paymnt_amt/date`（拼写 paymnt）、`caseier`、`modif_content`（应为 modify）、`colour_num` 在 summary 表为 int（色号却用整型）。
7. **状态/类型枚举跨表重复且口径不一**：备货 status(1..8)、report_period status(1..4)、prepare_type/prep_type/prep_category/stock_type 多套编码，语义重叠。
8. **字符集混用**：同域内 general_ci / unicode_ci / 0900_ai_ci 三种排序规则并存（import 表尤甚）。
