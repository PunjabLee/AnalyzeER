# M0 · 技术选型候选对比（图库 / 向量 / LLM）

> 唯一写入者：M0。锚点：`design-plan.md` §1.2、§4.3、§8.3-3；`RUNBOOK` C-1/C-2/C-2a/C-2b/C-3、N-3。
> **纪律**：Python3 已定为 MVP 运行时（过门决策）；**重型图库 / 向量库 / LLM 均为「由实测缺口触发的按需后置增强，非默认底座」**（§1.2/C-3）。凡未选定者一律 **[待确认]**，**不得**把候选写成既定事实。
> 本机能力矩阵为 M0 **实测**（`python3` 探测，非照抄 RUNBOOK）。

## 2. MVP 存储/图形态（与 C-2 一致，非重型引擎）

**结论（MVP 落地形态）**：**内存/JSON 属性图（邻接表）+ SQLite FTS5 索引**。
- 属性图 schema 见 `schema.md`；JSON/YAML 机读导出为核心交付（§7.1/R-4，落 `graphrag/out/meta/`）。
- 精确检索 = FTS5(BM25)；结构/多跳 = 内存邻接表 BFS/DFS；`confidence`/`evidence_level` 作边属性内存过滤。
- **理由**：本资产关系已结构化落盘、A 级主语料仅 349 表，确定性栈即足；重型引擎在 M0 无实测缺口支撑（§1.2）。

- 硬约束：社区检测**仅喂 `confidence ≥ 0.45` 边**；涌现簇 vs `00` 手工 18 域对照、不覆盖权威分组（§8.1-M3）。

## 4. 向量库（L 语义兜底）——按需后置、非默认 [待确认]

| 候选 | 定位 | 触发条件 |
|---|---|---|
| **不引入（默认）** | L1 FTS5+图遍历先测基线 | §1.2/§4.3：向量层仅在确定性基线命中率未达标时启用 |
| `sqlite-vec` / `faiss`(本地) | 轻量本地向量，契合"macOS 无重型服务" | 实测缺口=语义召回不足 |
| `pgvector` / `Milvus` | 服务型向量库 | 仅当规模化/多租户，超出本期单语料场景 → 倾向不选 |

- **结论 [待确认]**：MVP **不预设**向量库；`Table.name+域+含义`、文档块的向量接口在 schema 留位即可（§4.3）。

## 5. LLM / NL 前端（L3）——可选、受限 [待确认]

| 用途 | 定位 | 约束 |
|---|---|---|
| **LLM 抽取层** | **冗余可省**（§1.2/R-0） | 关系已由 `01/03/05` 结构化落盘，再抽既有失真又无增量 |
| 社区摘要生成 | 受限使用 | 不得新建确定性来源外的表/字段/关系；须回填 `SUPPORTED_BY`，否则降级 `[待确认]`（§4.2/R6） |
| AgenticRAG NL→结构化 | **可选前端**（非主链路） | 必落到 L1/L2 结构化调用，不绕过 `confidence ≥ 0.45`、不生成未 grounding 关系（§1.3-4/§6/R-5） |

- 具体 LLM 供应商/模型/是否本地 → **[待确认]**，本方案不预设。
