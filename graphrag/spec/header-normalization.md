## 2. 规范列（canonical）

归一目标 7 列（多退少补；`关联` 可缺省或内联）：

```
字段 / 类型 / 可空 / 默认 / 键-线索 / 含义 / 关联
```
- `键-线索` = 键（PK/UK/FK）与「主/外键线索」两类的统一列。
- `关联` 三态：① 独立列；② 内联于 `键-线索` 列，形如 `FK[目标表·依据]`；③ 与 `含义` 合列，形如 `含义 / 关联`（斜杠分栏）。三者解析后必须拆回独立的「键-线索」与「关联」语义。
- `可空`：`N` = NOT NULL → `nullable=false`；空/Y → `nullable=true`（结合 DDL 校验）。
- 缺 `默认` 列时 → `Column.default = null`（不代表无默认，代表文档未记，结构事实以 `test_erp.sql` 为准）。

## 4. 非字段辅助表头（03/ 内，实测 8 种 / 17 行）——**不得**喂给列解析器

这些表头描述的是问题清单/族规模/跨域映射/字典，而非逐字段列定义，解析规则不同（属 `Issue`/`SAME_FAMILY_AS`/关系边来源）：

| 磁盘原文签名 | 行数 | 归属处理 |
|---|---:|---|
| `\|编号\|问题类型\|说明\|` | 7 | → `Issue`（问题清单） |
| `\|编号\|问题类别\|描述\|涉及表/字段\|` | 3 | → `Issue` + `HAS_ISSUE` scope |
| `\|本域.字段\|目标域·表\|依据\|` | 2 | → 关系边/`REFERENCES` 线索 |
| `\|族\|代表结构数\|套数/副本数\|小计\|` | 1 | → `SAME_FAMILY_AS` / `member_count` |
| `\|关键差异字段\|类型\|含义\|` | 1 | → 族差异说明（非全列定义） |
| `\|分组\|字段（均 int NOT NULL DEFAULT 0，除首列）\|` | 1 | → 族归并说明 |
| `\|分组\|字段\|键/含义\|` | 1 | → 族归并说明 |
| `\|表\|中文含义\|name 含义\|` | 1 | → 表级登记（非列级） |

> 若把这些误判为字段表，将污染 `column_count`（触发 M1 §3 列数与 DDL 交叉校验 FAIL）。

## 6. 归一算法（M1 解析器契约，P0 必载）

1. **定位表头**：连续两行满足「首行以 `|` 框定、次行为 `|[-: |]+|` 分隔线」→ 首行为表头。
2. **规范化签名**：逐 cell `strip()`；对内空格不敏感匹配；命中 §3 白名单则按映射归一；命中 §4 则路由到非列解析；**未命中 → 记 `unmapped_header` 并告警**（禁止静默丢弃，抗新变体）。
3. **合并行拆回**（§3.3-2/R7）：字段单元格若含「审计四件套」类合并写法（`created_by/updated_by/created_at/updated_at`），**必须拆为原子列**，拆后 `column_count` 与 `test_erp.sql` DDL 交叉核对。
4. **`关联` 三态还原**：独立列 / 内联 `FK[目标·依据]` / 斜杠合列 `含义 / 关联` → 一律产出「键-线索」+「关联」两个字段，供 `RELATES_TO`/`REFERENCES` 消费。
5. **`DDL 行号` / `#` 列**：仅用于人工审计（尽力字段），**不入 `Column`**，映射见 §3 签名 11。
