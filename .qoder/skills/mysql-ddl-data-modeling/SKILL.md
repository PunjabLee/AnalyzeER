# MySQL DDL 逆向梳理数据模型

输入**任意一份 MySQL 建表脚本（DDL 文件）**，输出**按业务域组织的数据模型交付物集**。全流程只以当前指定 SQL 为唯一事实来源，每阶段自带校验检查点，检查点不通过不得进入下一阶段。

## 必须遵守（硬约束）

1. **唯一事实来源**：严格基于用户当前指定的 SQL 文件逐表核对，目标表集合中**一张不能遗漏、不能重复**。
2. **推断显式化**：凡 SQL 未明示的信息（关系、含义、归属）一律标注 `[推断]`（含五级依据）或 `[待确认]`，**禁止臆造关系**。
3. **禁止沿用旧结论**：不得用上轮/旧数据源的表数量、分组结果、ER 关系直接代替新版实测；数据源变更后相关产物必须重生成（可在差异检查阶段判定"增量更新"的除外）。
4. **口径先行**：数量等式（见终验）在任何阶段发现不成立时，先修复再交付。
5. **调整留痕**：分组或口径需要调整时，先在 `00-总览与分组清单.md` 记录调整说明，再继续执行，不中断等待确认。
6. **超长分批**：按业务域分批输出，每批开头声明本批覆盖表范围与累计完成数量；单文件过长时用"先整写、后追加替换"的方式分次写入，规避单文件行数限制。

## 交付物目录结构

```
er-model/
├── 00-总览与分组清单.md          # 事实基线+差异摘要+分级口径+域分组+数量校验+交付进度表
├── 01-ER图/Dxx-<域名>.md          # 每业务域一张 Mermaid erDiagram + 关系证据摘录表
├── 03-逻辑数据模型/Dxx-<域名>.md  # 每业务域逐表全字段 Markdown 表格
├── 04-C级备份与测试表清单.md      # C 级表点名与排除理由
├── 05-跨域核心关系总览.md         # 全局图(不展开字段)+核心实体三分类+模型问题清单
└── _*                             # 临时工作文件(_line_map.txt、_group.ps1 等)，终验后清理
```

模板全部见 [templates.md](templates.md)；普查与差异取证脚本见 scripts/ 节。

## 工作流（九阶段）

### 阶段 1：数据源普查

执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/ddl_census.ps1 -SqlFile <ddl.sql>`，得到并记录：

- CREATE TABLE 原始匹配数 vs 去重数（差异必须解释）；文件行数
- `FOREIGN KEY` / `CONSTRAINT` 计数 → 判定是否存在显式外键（决定关系证据分级起点）
- `PRIMARY KEY` 计数 + **无主键表清单**
- 表注释覆盖率（`) ... COMMENT='...'` 存在性）
- 表名前缀分布 → 识别平台/框架同构族（如 hex 后缀的应用复制表、每套 N 张的调度表、`*_bak_日期` 备份、`test_`/`copy1` 变体）
- 生成 `_line_map.txt`（`起始行|表名`，逐表 Read 定位用）

**检查点**：`_line_map.txt` 行数 = 去重表总数；内置检索工具（Grep 类）结果与 Select-String 计数交叉复核，不一致时以多通道复核为准。

### 阶段 2：数据源版本差异检查（存在旧版数据源/旧产物时必做）

执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/compare_ddl_sources.ps1 -OldSql <旧> -NewSql <新>`，得到：

- 新增 / 删除 / 保留表三个集合（校验：保留 = 旧∩新，无交集外残留）
- 保留表的**字段数变更取证**（全表逐一对比列数，输出变更表清单）
- 主键/外键线索有无变化、注释风格有无系统性变更

据此判定：**全部重做**（保留表存在字段级变更、或新增业务表规模足以改变分组/关系）vs **按差异增量更新**（仅新增表建产物、变更表重生成对应文档），并在 `00-总览` 写"差异摘要"章节。

**检查点**：新增+删除+保留 与两版总数满足集合恒等式；结论明确写入总览且注明判定依据。

### 阶段 3：A/B/C 分级覆盖口径

将全量表划为三级（表数记 A、B、C）：

| 级别 | 范围 | 处理深度 |
|---|---|---|
| **A 级** | 真实业务表 | 逐表全字段 ER + 逻辑模型 |
| **B 级** | 平台/框架同构表（按结构族识别，如每套 N 张 × M 组） | 每族展开 1 个代表，其余归类点名并标注"同构副本，不重复展开" |
| **C 级** | 备份表 / 测试表 / 明显临时表 | 仅清单点名 + 排除建模理由，可核验无遗漏 |

口径若导致部分表不进入逻辑模型，**必须与用户确认一次**（AskUserQuestion），确认后写入总览。

**检查点**：`A + B + C = 表总数` 硬校验；每张表归属唯一级别。

### 阶段 4：业务域分组（仅 A 级）

1. 用脚本按语义前缀自动归类（有序正则、首匹配生效——顺序即优先级，特例放前面防止贪婪误匹配，如 `^jf_product$|^jf_product_` 而非 `^jf_product`）。参考 scripts/ 中的规则结构，按当次表名清单定制域与规则。
2. 人工抽查校正：单复数/拼写变体、误吞词根、归属存疑表显式标注 `[待确认]` 或"按既定分组保留"。
3. 输出域清单（每域编号 Dxx、域名、表数、**逐表点名**）写入 `00-总览与分组清单.md`。

**检查点**：`Σ各域表数 = A 级数`；脚本比对分组结果与 A 级表集合：零遗漏、零重复（UNMATCHED=0 且无重名）。

### 阶段 5：关系推断与证据分级（核心）

每条关系必须标注五级依据之一（强度降序）：

| 标注 | 判定方法 |
|---|---|
| `[显式外键]` | DDL 存在 FOREIGN KEY 约束（普查为 0 时本库不会出现） |
| `[注释明示]` | 字段 COMMENT 点名目标表（如"关联 jf_xxx"、"xx表id"）——最强推断证据 |
| `[索引佐证]` | 该列建有 INDEX/UNIQUE 且列名以 `_id`/`_code` 结尾指向真实表 |
| `[字段命名]` | `xxx_id`/`xxx_code` 命名且目标表存在（无索引/注释佐证） |
| `[业务语义推断]` | 仅凭名称语义（varchar 存他表名称等弱范式） |

规则：

- 无外键的库，**所有关系一律为推断关系**，逐条带依据标注，禁止臆造。
- 目标表不存在、指向不明、类型对不上 → 标 `[待确认]` 并进入问题清单。
- 基数判定：默认 `1:N`；FK 侧存在 UNIQUE 索引 → `1:1`；双 `_id` 映射表 → `N:M`（拆成两条 1:N 经桥接表）。
- **跨域引用实体用桩（stub）表示**：在当域 ER 图中作为实体出现并注明 `[跨域引用·Dyy]`，不重复计数。

**检查点**：grep 全部关系行均含 `[` 依据标注；每条 `[注释明示]` 能在 SQL 原文中找到 COMMENT。

### 阶段 6：每域 ER 图输出

产出 `01-ER图/Dxx-<域名>.md`，遵循 templates.md 的 T2 模板：

- 一张 `erDiagram`：实体块（PK/UK/FK + 关键字段）、每条关系线格式
  `A ||--o{ B : "1:N [依据] a.col -> b.id"`（1:1 用 `||--||`，强制多行用 `||--|{`）
- 域内分组注释（%% 分隔主数据/交易/桥接）
- 文末附**关系证据摘录表**：逐条引用 SQL 的 COMMENT / INDEX 原文（可核验）

**检查点**：实体数 = 域表数 + 桩数；Mermaid 语法可渲染（关系字符串内不用引号嵌套）；文件头声明唯一事实来源与覆盖计数。

### 阶段 7：逻辑数据模型输出

产出 `03-逻辑数据模型/Dxx-<域名>.md`，遵循 templates.md 的 T3 模板：

- 文首图例：`可空 N=NOT NULL，Y=可空`；键列写法 `PK` / `PK(非自增)` / `UK` / `FK[目标表·依据]` / `[待确认]`
- 每表一节：`## n. 表名 — 中文含义`（含义来自表 COMMENT；缺失则"待确认"）＋表级说明（主键是否自增、索引、字符集/排序规则）＋**固定七列字段表**：
  `| 字段 | 类型 | 可空 | 默认值 | 主/外键线索 | 字段含义 | 与其他表的关联 |`
- 域末汇总本域问题条目（编号 `P-Dxx-0y`，见阶段 8 问题分类）

**检查点**：每表字段行数 = DDL 块内列数（用 `_col_counts.txt` 复核）；本域表数 = 分组计数；作废/冗余字段在含义列如实标注。

### 阶段 8：全局成果

产出 `05-跨域核心关系总览.md`，含三部分（模板 T4–T7）：

1. **跨域核心关系图**：只画核心实体与关系、不展开字段；规模大时按主题拆多张子图（主数据骨干 / 交易主干 / 资金链路 / 支撑域）。
2. **核心实体清单**：全部 A 级表按 **主数据 / 交易 / 配置字典** 三分类，校验三类数量之和 = A 级表数。
3. **模型问题清单**：按 **A–G** 大类组织——A 外键缺失、B 冗余与反范式、C 命名一致性、D 审计与逻辑删除字段、E 类型与主键问题、F 语义与归属、G 数据治理与安全。编号 `P-Dxx-0y`（域内问题）或 `P-G-01`（全局问题），逐条给出涉及表/字段、证据原文、影响与建议。

**检查点**：三分类和 = A 级数；问题清单条目可回溯到 SQL 原文。

### 阶段 9：终验与汇报

输出终验报告（模板 T8），必含：

- 等式校验链：`新版表总数 = A + B + C = Σ各域分组 + 桩不计入 = 已输出表数`；**未输出数 = 0、遗漏数 = 0**（全量表名清单与已输出文档表名做集合 diff）
- 新增 / 删除 / 变更表清单（来自阶段 2）
- 每批交付与提交的追溯表（提交哈希 + 说明）
- 清理 `_` 开头临时工作文件；`00-总览` 交付进度表置终态

**检查点**：集合 diff 为空；等式在报告中显式成立。

## 工程约定（Git 与批次）

- `.gitignore` 排除 `er-model/_*`（模板 T0）。
- 首次交付前做 **baseline commit**（数据源 + 总览 + 首批域产物）；之后**一批一提交、严禁混批**。
- 提交信息统一：`feat(D04): 应收/收款/结算域 ER图+逻辑模型（33 表，累计 306/1322）`；终验后做收尾提交 `chore: 终验通过，清理临时文件，进度表终态`。
- 批次建议顺序：先主数据锚点域（客户/商品类）→ 交易域 → 资金/票据域 → 字典与配置域 → B 级 → C 级 → 全局 → 终验；可按依赖微调但须全覆盖。

## 注意事项（工具踩坑，Windows/PowerShell 环境）

1. **脚本注释必须纯 ASCII**：PS 5.1 将无 BOM 的 .ps1 按 ANSI/GBK 解码，中文注释的乱码字节可能**吞掉行尾换行**，把下一条语句并入注释而**静默不执行**（无任何报错，产生全错的结果）。技能自带脚本已改为英文注释；生成任何临时 .ps1 时同样只写 ASCII 注释，中文说明放在 .md 文件里。
2. 经 Bash 类工具向 powershell 传单行命令时：`$var=...` 开头的赋值与反引号转义符（`` `t `` `` `n ``）会被外层转义吞掉导致命令碎裂——多语句逻辑一律**写成 .ps1 文件后 `-File` 执行**；Tab 用 `[char]9`；避免以双引号字符串拼接输出，改用 `Write-Output` 或分号分隔的裸表达式。
3. C 风格强转 `(string)$x` 在部分环境解析失败，统一用 `[string]$x` 或 `$x.ToString()`。
4. 终端被强制为 PowerShell，`cmd /c` 类命令不可用；`Get-ChildItem | Select-Object -ExpandProperty Name` 类管道输出可能被渲染吞掉——**列目录/找文件优先用 Glob/Read 等文件工具**，shell 只做统计计算。
5. 内置文件内容检索工具对大文件结果可能截断/不可靠：**计数与清单以 Select-String（或脚本）独立通道复核**为准；同一文件不同工具行数可能不一致（换行符/编码差异），全流程锁定同一工具（Get-Content 数组索引）作为行号基准。
6. 表名正则要放宽：兼容 `IF NOT EXISTS`、可选反引号、`(` 前多空格、Navicat 风 `) ENGINE = InnoDB ...` 与大小写表名（统一 ToLower 后比较），否则漏计。
7. Read 类工具返回带 `行号→` 前缀，属元数据，**严禁写入交付文件**；精读大文件按 `_line_map.txt` 行号分块读取。
8. 大文件逐表取证优先用脚本（scripts/）一次产出全量列数，避免逐表人工读；脚本结论与历史实测不符时，先用小型夹具（fixture）回归脚本本身再下结论。

## scripts/ 用法

- [scripts/ddl_census.ps1](scripts/ddl_census.ps1)：阶段 1 普查（执行）。输出总表数/外键数/无主键表/注释覆盖率/前缀分布，生成 `_line_map.txt`、`_col_counts.txt`。
- [scripts/compare_ddl_sources.ps1](scripts/compare_ddl_sources.ps1)：阶段 2 差异取证（执行）。输出新增/删除/保留集合与各表列数变更清单，生成 `_diff_*.txt`。
- [scripts/group_by_domain.ps1](scripts/group_by_domain.ps1)：阶段 4 分组模板（读入后按当次表清单改写规则段再执行）。有序正则首匹配 + 零遗漏校验。
